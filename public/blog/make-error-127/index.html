What does Make Error 127 mean?

GNU make runs recipe lines through a shell—normally /bin/sh unless the Makefile sets SHELL. When that shell cannot locate a command, it returns status 127. GNU make then prints the recipe failure as Error 127 and stops the affected target.

/bin/sh: gcc: command not found
make: *** [Makefile:42: obj/main.o] Error 127

When the binary name appears in the make line itself:

make: go: No such file or directory
make: *** [Makefile:18: build] Error 127
THE DETAIL MOST GUIDES MISS The printed 127 and make’s own exit status are different layers.

Error 127 is the recipe shell’s status. GNU make itself normally returns 2 after it encounters an error. In CI, the log may show the missing command as 127 while the make process is reported as exit code 2.

How to find which command triggered Makefile Error 127

1

Read the full make output

Find the line above Error 127. It names the missing binary (go, gcc, g++) and often the Makefile line number.

2

Open the makefile at that line

Run make -n target for a dry run, or sed -n to print the recipe block.

3

Confirm the binary exists

Run which go gcc g++ python3 and echo $PATH in the same shell environment make uses.

4

Re-run with verbose make

make V=1 or make --debug=v helps when nested scripts hide the failing command.

INTERACTIVE COMMAND CLINIC

Match the line above Error 127

The final make line is only the messenger. Select the command the shell could not find.

ROOT CAUSE Missing command: uv

The Makefile calls uv, but that executable is absent from the environment or outside PATH.

command -v uv
printf '%s
' "$PATH"

Fix: Install uv in the same CI image or shell that runs make, then verify with command -v uv.

command -v go on your laptop proves nothing about a Docker build stage, CI runner, Kubernetes Job, cron environment, or another user’s shell. Environment mismatch is the recurring cause behind “it works in my terminal.”

Fixes by environment

The same root cause shows up differently on a laptop, in Docker, in CI, or under WSL.

Fix path: Local development

    GNU make error 127 command not found: common causes

    Compiler not installed

    g++ or gcc missing on a fresh VM or minimal CI image.

    Fix: sudo apt install build-essential or dnf groupinstall "Development Tools".

    make: go: No such file or directory

    Go project makefile calls go build but Go is not on PATH in CI or Docker.

    Fix: Install Go, use actions/setup-go, or a golang base image before RUN make.

    Wrong PATH in make

    Interactive shell has /usr/local/go/bin; non-interactive sh used by make does not.

    Fix: Export PATH in the Makefile, CI job, or run PATH="/usr/local/go/bin:$PATH" make.

    Typo in recipe or CC variable

    Unset CC or a typo yields sh: ccX: command not found.

    Fix: Run make -p or add $(info CC=$(CC)) temporarily to verify variables.

    Alpine / musl mismatch

    Dockerfile uses alpine but the makefile assumes bash or GNU coreutils.

    Fix: apk add make gcc musl-dev bash before make in the image.

    WSL vs Windows host

    Tools installed on Windows but make runs inside WSL without Linux binaries.

    Fix: Install gcc, make, and go inside WSL; export PATH in ~/.profile.

    Makefile patterns that prevent Error 127

    GO := $(shell command -v go 2>/dev/null)
ifndef GO
$(error go not found in PATH — install Go or export PATH)
endif

    Document dependencies at the top of the Makefile: # Requires: gcc g++ make python3.

    FAQ

    GNU make ran a recipe and the shell returned exit status 127 because a command in that recipe was not found. Fix the missing binary or PATH, not make itself.
    Error 127 in the make output is the recipe shell status: command not found. GNU make itself normally exits with status 2 after encountering an error. The printed recipe status and the final make-process status are related but not identical.
    Your interactive shell loads .bashrc or .zprofile and adjusts PATH. Non-interactive shells used by make, CI, and cron may not. Export PATH in the Makefile, CI config, or job wrapper.
    Install Go and ensure go is on PATH for the same user and environment that runs make. In CI, use an official setup action or a golang container image.
    The shell could not execute a program named in the makefile recipe. Read the line above Error 127, install that tool, then run make again.
    The recipe calls uv, but uv is not installed or is outside PATH in the environment running make. Run command -v uv and make -n for the target, then install uv in the same CI image, container, or user environment.
    Not necessarily. Native Windows error codes, installer errors, and game errors can reuse the number 127 with unrelated meanings. This guide covers GNU make and POSIX-style shells where 127 means command not found.
