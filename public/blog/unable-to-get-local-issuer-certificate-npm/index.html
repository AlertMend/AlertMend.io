The safe answer

Do not disable npm SSL verification.

The npm error unable to get local issuer certificate means npm or a Node process could not build a trusted TLS certificate chain for the registry it is contacting.

The right fix is to identify the registry/proxy/private CA, add the correct trusted CA, and verify the result with npm ping or the failing npm install command.

What “unable to get local issuer certificate” means in npm

npm is trying to talk to a registry over HTTPS. During the TLS handshake, the server presents a certificate chain. npm/Node must be able to connect that chain back to a trusted root certificate. If the local trust store does not contain the issuer that signed the chain, npm fails with messages such as unable to get local issuer certificate, UNABLE_TO_GET_ISSUER_CERT_LOCALLY, or self signed certificate in certificate chain.

TL;DR: the registry may be healthy and your package may be fine. The failing layer is trust: corporate proxy CA, private registry CA, stale CA bundle, Docker image CA store, or CI runner configuration.
Pick your environment

Same npm error. Different real fix.

Choose where the error appears. The command that fixes a laptop may not fix a Docker image or CI runner.

$ observed failure npm ERR! request to https://registry.npmjs.org/ failed, reason: unable to get local issuer certificate
Interpretation

Your Node/npm trust store cannot validate the registry chain.

Start by confirming the registry URL and whether the failure happens only on one machine, VPN, or network. If the public registry works elsewhere, the issue is local trust or proxy configuration.

npm config get registry
npm ping
npm config get cafile

Fix: Update Node/npm if very old, check OS certificates, and add the correct CA only if your environment uses one.

Safe fix checklist

Do these in order. The goal is to restore trust for the right certificate authority, not to silence TLS verification.

1

Confirm the registry

Run npm config get registry. If it points to Artifactory, Verdaccio, Nexus, GitHub Packages, or another internal host, fix that host’s CA chain first.

2

Check proxy settings

Look at npm config get proxy, npm config get https-proxy, HTTPS_PROXY, and NO_PROXY. A proxy can replace the certificate you see.

3

Add the trusted CA

Ask security/IT for the corporate or registry root CA in PEM format, then configure npm with npm config set cafile /path/to/ca.pem.

4

Verify with npm

Keep strict-ssl=true, then run npm ping and the original npm install or npm ci command in the same shell.

SituationBest fixWhy it works
Company laptop on VPN npm config set cafile /path/to/company-root.pem npm trusts the CA that signs the proxy or internal registry certificate.
Node app or postinstall script fails NODE_EXTRA_CA_CERTS=/path/to/company-root.pem Node processes can extend their known root CAs when they start.
Docker image fails but laptop works Install OS CA package and copy the corporate CA into the image. Containers have their own filesystem and trust store; your laptop trust does not automatically follow.
Private registry has incomplete chain Fix the registry certificate chain on the server or load the issuing CA. Clients need the full chain from leaf certificate to trusted issuer.

CI and Docker: why the fix disappears

A common trap: you fix npm on your laptop, then the build still fails in GitHub Actions, Jenkins, GitLab CI, or a Dockerfile. That is expected. The CI runner and container image have separate environment variables, npm config, and CA stores.

Docker pattern

FROM node:22-bookworm
COPY company-root.pem /ca/company-root.pem
ENV NODE_EXTRA_CA_CERTS=/ca/company-root.pem
RUN npm config set cafile /ca/company-root.pem
RUN npm ping
RUN npm ci

CI pattern

npm config get registry
printf "%s" "$COMPANY_ROOT_CA" > company-root.pem
export CA="$PWD/company-root.pem"
npm config set cafile "$CA"
export NODE_EXTRA_CA_CERTS="$CA"
npm ping
npm ci
Production rule: store the CA as a managed secret or baked image asset, not as an ad-hoc command typed by the on-call engineer during a failing deployment.

What not to do

Anti-pattern

npm config set strict-ssl false

That command may get a build moving, but it also tells npm to stop verifying registry certificates. It converts a trust-chain failure into a hidden supply-chain risk. If you use it for a minute to confirm the diagnosis, immediately undo it with npm config set strict-ssl true and implement the CA fix.

How to automate this class of npm certificate failure

Certificate failures are good automation candidates because the evidence is repeatable: registry URL, npm config, proxy variables, Node version, container image, runner identity, certificate expiry, and the failing command. A useful automation should collect that evidence first, then choose a safe action.
